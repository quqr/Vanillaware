# 0020 — 收录的每个格式都必须字节级闭合

> 状态：已采纳（2026-10-27）

## 背景

库的目标是「像文件浏览器一样看原生资源」。在 0013/0018 之后，注册表里 26 个扩展名
都至少有 `doc` 查看器，但其中一批只是「头部 + 前 16 个 u32 + 可打印串」的通用二进制视图：
`.nnd`、`.drg`、`.ufb`、`.ucb`、`.acb`、`.awb`、`.acf`、`.usm`、`.vs2`、`.inc`。
这类视图能证明「文件被打开了」，不能证明**解析器读懂了它**——同一份 0x200 字节头部，
既可以是一个合法结构的前缀，也可以是恰好长得像的噪声。

## 决定

**收录集合内不再保留"只看头部"的格式。** 每个扩展名必须满足：

1. **字节账平** —— 解析器把每个字节归到一个具名段（头 / 表 / 池 / 载荷 / 尾），
   允许"载荷不透明"（HCA、Sofdec2 帧），但不允许"剩余 N 字节不知是什么"；
2. **有校验项** —— 每条不变量是一个 `check`，id 形如 `<fmt>.<invariant>`，
   在查看器里逐条显示 ok/FAIL；断言写在模块顶部文档里；
3. **全量跑过语料** —— 不是抽样。验证入口是 `cargo run -p vw-formats --example doc_probe -- <文件…>`，
   它打印每个文件的节点数与全部 check，任何 FAIL 都以非零码退出；
4. **语义不臆造** —— 字段含义没有代码或官方口径支撑时，用位置名（`w0`、`f2`、`field4`）
   并在文档里说明"语义未定"，不写看起来很像的猜测名。

`.cpk` 是唯一的例外：目录表加密、romfs 已全量解包，按用户决定**不投入**，
它留在 `Kind::Binary`，只有元信息视图。

## 落在哪

| 格式 | 模块 | 关键不变量 | 语料 |
|---|---|---|---|
| `.acb` / `.acf` | `doc/utf.rs` + `doc/acb.rs` | `@UTF` 表：行宽 == 列宽之和、表长 + 0x08 不越界 | UO 8 + 13 侧 14、acf 1，全过 |
| `.awb` | `doc/awb.rs` | 总大小 == 文件长、偏移严格递增、首条 == 描述区末尾、末条 == EOF | UO 6 + 13 侧 6，全过 |
| `.usm` | `doc/usm.rs` | 块链（0x20 对齐）末尾 == 文件长 | 13 侧 22 个，全过 |
| `.ufb` | `doc/ufb.rs` | 记录/网格/F 记录/u32 表/字符串池五段首尾相接，slack == 0 | `Field.ufb` 147 MB，slack 0 |
| `.ucb` | `doc/ucb.rs` | `1311 组 × 2199 条 × 0x20 == 文件长`，索引与组号由序号推出 | `Field.ucb` 92 MB，全过 |
| `.drg` | `doc/drg.rs` | 数据库表 `96 × 0x90` 与命令区偏移对齐、命令表 `6559 × 0xD0` 到 EOF（末条短 0x10） | 2 个，全过 |
| `.vs2` | `doc/vs2.rs` | `16 + N × 12 == 文件长`、id 段单调不减 | 1 个（N = 17280），全过 |
| `.nnd` | `doc/nnd.rs` | 载荷 `wordCount % 3 == 0`；尾部按「前导字 / 名字槽 / 表体」归段且恰好到 EOF | 302 个，全过 |
| `.inc` | `doc/text.rs` | 编码/BOM/换行判定 + 行数 | 15 个，全过 |

## 后果

- **新增格式的成本变高**：注册表加一行已经不够，必须同时给出「读到哪算完」的判据，
  否则它进不了收录集合。这是想要的摩擦。
- **验证脚本进仓库**：`examples/doc_probe.rs` 是唯一的语料验收入口，改解析器先跑它。
  （注意它输出的是 check 结果，`nnd.shape` 这类**描述性字段**不算校验。）
- **语义未定的字段浮在表面**：`nnd` 的三字组、`drg` 记录尾部的 4 个 u32、`ucb` 的类型常量
  都没有被包装成"已知字段"。以后有代码证据时再改名，而不是先把猜测写进去。
- **载荷边界写清楚**：`.awb` 的 HCA（子密钥加密）、`.usm` 的 Sofdec2 帧、`.ftx` 的 NVN
  块布局都停在容器层，这一层之外不解码，也不声称解了。
