# ADR-0002：缩略图采用磁盘二级缓存，不扩展解析器接口

- **状态**：已接受（2026-10-20）
- **影响范围**：File Manager 缩略图管线、磁盘占用、启动耗时

## 背景

`UnifiedFtexReader.ParseFile` 一次调用会读入整个文件、必要时做 FCMP 解压，并由平台解析器把**每一帧都解码成原始像素**（`ImageResult.PixelData`）。`IFtexParser` 没有「只读头部/只取帧数」的路径。

加载阶段为了在卡片上显示「图片张数」，对每个 FTX 调用了 `ParseFtx`，随后立刻丢弃全部像素。实测规模约 1060 个 FTX，等于每次打开文件夹都把整批资源完整解码一遍，且后续每切换一帧缩略图又会重新解析该文件。

## 决策

- 加载阶段**不解析任何文件内容**，只建立资产单元（文件路径、配对状态）。
- 卡片被虚拟化容器实例化时才触发解析；一次解析顺手把每帧缩到 256px 写入磁盘缓存，并写 sidecar 元数据。
- 缓存位置：`%LOCALAPPDATA%\QuadToSpine2D\thumbs\<pathHash>\`，包含 `000.png`、`001.png`… 与 `meta.json`。
- 缓存键：规范化完整路径的哈希（目录名）+ `meta.json` 中的 `mtimeUtc` 与 `size`（失效判定）+ `schema` 版本号。
- `meta.json` 记录帧数、每帧尺寸、源文件 mtime/size，使「帧数徽标」在二次打开时无需解码即可获得。
- 帧数徽标允许**懒出现**：卡片尚未实例化时徽标为空，滚动到时才填充。不做后台全量补全。
- 提供「清空缩略图缓存」入口。

## 权衡

- 首次打开大目录仍然是慢的，但由「同步阻塞」变成「滚动到哪、哪里出图」，UI 不再冻结。
- 第二次打开同一目录时，帧数与缩略图都不需要解码，接近瞬时。
- 新增一份磁盘占用（256px PNG，量级为每帧数十 KB）与失效/清理责任。
- 不触碰 8 个平台解析器，避免在已知重复的代码上继续加债。

## 备选方案

- **扩展 `IFtexParser` 增加只读头部方法**：首次打开即可拿到精确帧数且无磁盘副作用，但需要在 8 个已经高度重复的解析器里各实现一遍，风险与维护成本更高。保留为后续可选优化——若未来缓存目录不可写，可作为降级路径。
- **纯内存 LRU**：不产生磁盘副作用，但每次打开文件夹都要重新解码，对 1000+ 资产不可接受。
