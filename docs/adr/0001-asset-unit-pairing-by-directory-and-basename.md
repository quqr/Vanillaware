# ADR-0001：资产单元以「目录 + 基础名」为配对键

- **状态**：已废弃（2026-10-21，由 ADR-0012 取代：配对降为派生关联）
- **影响范围**：File Manager 页面的扫描、显示、导出

## 背景

File Manager 会递归扫描用户选择的根目录，并把 `.ftx`（纹理）与 `.mbs`（动画）归并成一张卡片（资产单元）。

现有实现只按 `Path.GetFileNameWithoutExtension(...)` 分组（`FileManagerViewModel.LoadFilesInternalAsync`），目录不参与配对键。这带来两个问题：

1. **跨目录误配**：递归扫描 `13rim dlc ex` 这类根目录时，不同子目录下的同名文件会被判成一对，而它们很可能毫无关系。
2. **静默丢弃**：同一基础名下出现多个文件时（例如 `.ftx` 与 `.ftp` 并存），`FirstOrDefault` 只取第一个，其余文件从视图中消失，导出时也就丢了。

实测数据：单个根目录下 1060 个 `.ftx` 集中在 `Animation\`，另有 10 个在 `Illust\`、各 1 个在 `Game\` 与 `Font\`。已确认 `.mbs` 与对应 `.ftx` **位于同一目录**。

## 决策

- 配对键为 **（所在目录的绝对路径，小写化基础名）**。
- **跨目录不配对**。同名但不同目录的文件是两个独立的资产单元。
- 同一配对键下若命中多个文件，**不丢弃任何一个**：全部挂在同一资产单元上，并标记为 `Ambiguous`，在 Inspector 中列出。
- 资产单元是浏览、筛选、导出、预览的唯一操作对象（见 `CONTEXT.md`）。

## 权衡

代价：如果将来遇到「纹理与动画分目录存放」的数据集，此规则会退化成「全部未配对」，届时必须修改本 ADR 并引入跨目录回退策略。

收益：误配不可能发生；不会静默丢文件；配对结果只依赖文件系统路径，无需索引数据库。

## 备选方案

- **仅按基础名跨目录配对**：能兼容分目录布局，但会产生静默误配，且必须额外设计消歧规则——对一个只读浏览工具来说，误配比未配对更难被发现。
- **引入索引/数据库记录配对关系**：违反「打开文件夹即用、零配置」的定位。
