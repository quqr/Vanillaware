# ADR-0023：`.bst` 是带类型标签的值流，不是节点树

- 状态：已采纳
- 日期：2026-10-28
- 相关：ADR-0022（`.oeb` / `.orb` 与 `.osb` 同族）

## 背景

`.bst`（13 Sentinels 的战斗关卡，`EX DATA/BattleStageData/`，43 个，159 KB～383 KB）
在 ADR-0022 时只解到「头部 + 名字区 + 大写标识符」，条目区标为未闭合。
当时的判断是「不是 `.osb` 族的节点树」——这一点是对的，但结论下得太早：
它根本不是节点树，而是另一套序列化器。

## 决定

把 `.bst` 解析成**带类型标签的值流**：

```text
+0x00 char[4] "BBST"
+0x04 u32     0（版本）
+0x08 u32     0
+0x0c u32     0
+0x10 u32     关卡计数（语料 116～118）
+0x14 u8      名字表首字符相对 0x10 的偏移（恒 0x0b）
+0x15 u8      恒 1
+0x16 ...     值流
```

值流每条是 **1 字节标签 + 定长载荷**，`0x34` 是记录结束符：

| 标签 | 载荷 | 含义 |
|---|---|---|
| `0x05` `0x06` | i32 | 整数（两个变体，语义未区分） |
| `0x08` | f32 ×2 | 双浮点（语料 1 处） |
| `0x09` | f32 | 浮点 |
| `0x0b` | u8 | 布尔 |
| `0x14` | RGBA | 颜色 |
| `0x15` | u32 | 整数（语料 1 处） |
| `0x1f` | f32 ×2 | vec2（UV / 法线 / 平面坐标） |
| `0x20` | f32 ×3 | vec3（角点 / 位置 / 包围盒） |
| `0x23` | f32 ×16 | 4×4 矩阵（语料 1 处） |
| `0x28` | u32 长度 + UTF-8 + NUL | 字符串 |
| `0x33` | u32 个数 | 数组 |
| `0x34` | — | 记录结束 |

### 数组元素有两种形态

同一个序列化器写了两种数组，靠**元素类型**区分（写入端知道，读入端靠 schema）：

- **标量数组**：`0x33 n` 之后跟 n 个值。角点索引 `[45, 162, 327, 593]`、边线 vec2 都是这种。
- **记录数组**：`0x33 n` 之后跟 n 条「若干值 + `0x34`」的记录。

语料里记录数组**每个文件恰好一处**，位置固定在记录的第二项：

```text
int 621            ← 顶点数
array 522 [ … ]    ← 522 块碰撞板，每块以 0x34 收尾
0x34               ← 关闭这条记录
```

所以判据写成：**只有「记录的第二项是数组」时才试记录解释**，其余数组一律按标量。
结果是 43/43 个文件读到 EOF 恰好用尽。

尝试过但**不成立**的判据（都记下来，避免重走）：

- 「数组读完 n 个值之后必须紧跟 `0x34`」——角点数组成立，碰撞板数组不成立；
- 「数组读完 n 条记录之后必须紧跟 `0x34`」——碰撞板数组成立，角点数组不成立；
- 「按记录数当元素数」对两种形态不通用。

### 记录形态

- **舞台头**（每文件 1 条，16 个值）：`fmd 名 / ftx 名 / 4 角 vec3 / f32 / 4 色 / 3 bool / 波次生成器数组`；
- **碰撞板**（10 个值）：`1, 0, 0, "", bool, bool, id, 中心 vec3, 0, 角点索引数组`，角点索引都落在
  记录前面那个「顶点数」范围内；
- **地形块**（44 / 52 个值）：4 个角点 vec3 开头，随后是名字、若干标志、包围盒与半径。

### 数组里可能出现 `0x34`

`array 386` 的 386 个元素里有 7 个是 `0x34`——计数把结束符也算作元素。
所以数组层必须把 `0x34` 当成一个可消费的值，否则这一条记录必挂。
（这也是「`0x34` 只是记录结束符」这个简化说法唯一的例外，如实写进代码注释。）

## 后果

- `.bst` 的查看器从「头部 + 标识符」升级为 `content`（碰撞板表 / 地形块表 / 俯视位图）
  与完整文档树，注册表类别从 `List` 改为 `Scene`。
- 俯视位图把地形块的四个角连成轮廓、再点上碰撞板中心，能直接看出关卡布局
  （矩形地块 + 河道 + 板中心分布）。
- 未定的语义如实保留：`0x05` 与 `0x06` 的区别、碰撞板的第二/第三个字段、
  地形块 44/52 两种变体差在哪，都没有编名字。
- 验收：`examples/bst_probe.rs` 打印记录/碰撞板/地形数与闭合位置；
  `examples/doc_probe.rs` 跑 `bst.magic` / `bst.names` / `bst.closed` 三项检查。
  43/43 全部 `bad=0`。
